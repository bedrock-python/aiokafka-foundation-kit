# Project profile

## About

- What this repository is: `aiokafka-foundation-kit`, an async Kafka foundation library for Python, published on PyPI. It provides settings, client factories, lifecycle helpers, topic management, health checks, DI wiring and OpenTelemetry on top of aiokafka.
- Who uses it: asyncio services that produce to or consume from Kafka with aiokafka.
- Language, version and main frameworks: Python 3.11 and newer, asyncio only. The one runtime dependency is `aiokafka>=0.12.0,<1.0.0`. Optional extras: `models` (Pydantic settings), `orjson`, `dishka`, `dependency-injector`, `telemetry` (OpenTelemetry) and `all`. The integrations live in `aiokafka_foundation_kit/contrib/`.
- Where the documentation lives: https://bedrock-python.github.io/aiokafka-foundation-kit/, built with Zensical from `docs/` (`zensical.toml`) and published by `.github/workflows/docs.yml` on every push to `master`. `docs/agents.md` is the one-page reference for coding assistants.

## Commands

| Task | Command |
|---|---|
| Install dependencies | `uv sync --group dev --all-extras` (`make install`). Without `--all-extras`, pytest fails at collection: `tests/unit/contrib/` and `tests/integration/` import Pydantic and Dishka. |
| Format | `make fmt`: `uv run ruff format .`, then `uv run ruff check --fix .` |
| Lint and type-check | `make check`: `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy aiokafka_foundation_kit` |
| Test | `make test-unit` (`uv run pytest -m unit`), no Docker needed. `make test-integration` (`uv run pytest -m integration`) needs Docker, and so does `make test`, which runs both with the 90% coverage gate. CI runs `uv run pytest -m unit --cov=aiokafka_foundation_kit --cov-report=xml --cov-fail-under=90` on Python 3.11, 3.12 and 3.13, and `uv run pytest -m integration` once. |
| Run locally | A library: nothing to run. The docs: `make docs-serve`. |
| Stop the local run | Ctrl+C in the terminal of `make docs-serve`. |

## Conventions

- Default branch: `master`. Changes reach it only through a pull request that passes the `All checks passed` check (ruleset `master-rules`). The pre-commit hook `no-commit-to-branch` refuses local commits to it.
- Issue tracker: GitHub Issues of this repository; refer to an issue as `#123` (`Closes #123` in the pull request template).
- Branch names: `<type>/<short-description>`, such as `feat/my-feature`, on a fork (CONTRIBUTING.md).
- Commit messages: Conventional Commits, enforced by the `conventional-pre-commit` hook. `uv run pre-commit install --hook-type pre-commit --hook-type commit-msg` installs every hook; CONTRIBUTING.md installs only the commit-message one, so ruff does not run at commit time. Pull requests are squash-merged. release-please reads the squash commit's title, which is the pull request's title, or the commit's subject when the pull request has one commit, so both must be Conventional Commits.
- Language of pull request titles and descriptions: English.
- Where specs and design notes go: in the pull request description; the repository has no place for them.

## Boundaries

- `CHANGELOG.md` is generated by release-please: never edit it by hand, and never add an `## [Unreleased]` section, even though the pull request template's checklist asks for one.
- `docs/changelog.md` is a copy of `CHANGELOG.md` made by `make docs-serve`, `make docs-build` and the Docs workflow. It is in `.gitignore`: never commit it.
- The version lives in `aiokafka_foundation_kit/__version__.py`, on the line marked `# x-release-please-version`, and in `.release-please-manifest.json`; release-please bumps both. Never change them by hand.
- `docs/agents.md` is part of the public API: it changes in the same pull request as the API (CONTRIBUTING.md, "The agents page").
- Files from the engineering-assets hub (`AGENTS.md` explains how it works) include the copy-page files (`docs/assets/javascripts/copy-page.js`, `docs/assets/stylesheets/copy-page.css`, `overrides/main.html`, `scripts/emit_markdown.py`), `.github/workflows/docs.yml`, `.github/workflows/release-please.yml`, `.github/dependabot.yml`, `.editorconfig` and `CODE_OF_CONDUCT.md`. Change them in the hub; a change here makes the file this repository's own.
- Never publish to PyPI or create a release by hand: release-please creates the release, and `publish.yml` publishes it.

## Notes

- Releases: release-please opens its pull request with the workflow's own token, so CI does not start on it. Close and reopen the release pull request to run CI, then merge it. `publish.yml` publishes to PyPI when the Release Please run on `master` completes and the commit carries an `aiokafka-foundation-kit-v*` tag. Only `feat`, `fix`, `perf` and `revert` commits make a release. Before 1.0, a breaking change bumps the minor version (`release-please-config.json`).
- Tests: `tests/conftest.py` sets the marker from the directory. Tests under `tests/unit/` get `unit` and tests under `tests/integration/` get `integration`, so a new test needs only the right directory, not a marker (`--strict-markers` is on). `tests/integration/` starts one Kafka broker per session with testcontainers. Tests are named `test__<subject>__<case>__<outcome>` and laid out as `# Arrange`, `# Act`, `# Assert`.
- Architecture: the core (`config/`, `producer/`, `consumer/`, `topics/`, `health/`, `utils/`) needs only aiokafka and takes its settings as `typing.Protocol`s. Everything that needs an extra lives in `contrib/`, which the package root does not import. `utils/json.py` uses `orjson` when it is installed.
- Code style (CONTRIBUTING.md): type hints on every function. mypy enforces them only in `aiokafka_foundation_kit/`, and the existing test functions have no return annotations. Google-style docstrings on the public API only; lines up to 120 characters; double quotes; comments only for a non-obvious why.
